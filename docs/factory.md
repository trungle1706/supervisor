# Agent factory (phase 12B): schemas and harness

WP-F1. Pure modules in `src/supervisor/factory/`; no flag. The one route sits behind
`ONBOARD_FACTS`. The platform locks the schemas, the tool registry and the mandatory guardians.
A team edits the listed fields only. All limits are in one file, `src/supervisor/factory/caps.py`;
the tables below are generated by hand from it, and a change to a cap is a platform change.

## Schemas

Three frozen schemas, version 1. Each is a pydantic model with `extra=forbid` (an unknown key is
refused and named). No float anywhere: counts and scores are integers, confidence is an enum.

```text
 facts card ---- GET /v1/facts/{node_id}/export ----> facts_v1
 agent definition (YAML or JSON) ---- validate ----> agent_definition_v1
 agent run ------------------------------------------> assessment_report_v1
```

Windows cmd:

```text
python -m supervisor.factory validate tests\factory\data\agent_single_pass.yaml
python -m supervisor.factory validate report.yaml --schema assessment_report_v1
python -m supervisor.factory schema agent_definition_v1 > agent_definition_v1.schema.json
```

`validate` prints `[OK]` and exits 0, or one `[FAIL] <field>: <message>` line per error and exits 1.
It never prints a traceback. For an agent definition it also checks the registry files (tool ids,
modes, scope kinds, group, owned dimension).

### facts_v1 (export of the facts card)

| Field | Type | Note |
|---|---|---|
| `version` | `1` | frozen |
| `node_id`, `attempt_n`, `latest_attempt`, `newer_attempt` | text, int or null, int or null, bool | from the card |
| `total`, `dropped_claims` | int | counts |
| `facts[]` | `FactRecord` | one per fact, in card order |
| `summary` | `SummaryRecord` or null | the build summary row (`kind=summary`) |

`FactRecord`: `fact_id`, `node_id`, `attempt_n`, `kind`, `name`, `detail`, `file`, `line`, `quote`,
`source` (`rule` / `model`), `confidence` (`low` / `medium` / `high`), `model_id`,
`dropped_claims`, `created_at`. Kinds: `tool`, `model`, `endpoint`, `dataset`, `file`,
`secret_use`, `external_url`, `mcp_server`, `approval_point`, `autonomy`, `decision33`,
`weak_spot`, `claim`.

`confidence` is not stored on a row. It is derived: a rule fact is `high`, a model fact is
`medium` (a model claim that passed `validate_llm_claims`). Drift rule: a test fails when
`onboard.facts.row_view` or `FactsService.card` gains a field that the export does not carry, or
when the fact kinds differ. Add the field to `facts_v1.py` on purpose.

Route: `GET /v1/facts/{node_id}/export`, permission `systems.view`. Off (`ONBOARD_FACTS=0`):
HTTP 400 `facts_off`. A node with no built card answers an export with `attempt_n: null` and no
facts.

### assessment_report_v1

`report_id`, `agent_id`, `agent_version`, `system_id`, `dimension_id` (one of the eight:
`model`, `data_governance`, `cybersecurity`, `legal_compliance`, `ethics`, `third_party`,
`supply_chain`, `reputation`), `findings[]`, `summary`, `model_id`, `harness_trace`, `created_at`
(RFC 3339 UTC, `...Z`).

* `findings[]`: `finding_id` (unique), `checklist_id`, `verdict` (`pass` / `fail` /
  `not_applicable` / `question`), `evidence[]`, `rationale` (at most 600 characters),
  `confidence` (`low` / `medium` / `high`).
* `evidence[]`: `kind` (`fact` / `document` / `regkb` / `pack` / `system_record`), `ref`, `file`,
  `line` (a line needs a file). **A finding with verdict `pass` or `fail` and no evidence is
  invalid.**
* `summary`: `total`, `passed`, `failed`, `not_applicable`, `questions` (integers; must equal the
  counts of `findings`).
* `harness_trace`: integers and pointers per component: `system_prompt`, `context`, `memory`,
  `hitl`, `verification`, `loop` (with `stopped_by` and `per_iteration[]` holding the score and a
  pointer `reason_ref` to the logged evaluator reason). It never holds document text.

### agent_definition_v1

| Field | Locked or editable | Rule |
|---|---|---|
| `schema_version` | locked | `"1.0"` |
| `id` | immutable | lowercase letters, digits, hyphen; at most 64 |
| `name` | editable | 1 to 64 characters |
| `description` | editable | 1 to 1,024 characters |
| `owner_group` | set at creation | `model_risk`, `data`, `cyber`, `legal`, `third_party`, `ethics`, `platform` |
| `dimension_id` | set at creation | one of the eight; the group must own it |
| `policy_refs[]` | editable | `doc_id`, `source` (`regkb` / `internal`), `version`, `sections[]`; at most 20 |
| `checklist[]` | editable | `id`, `question` (at most 500), `evidence` kinds, `severity` (`low` / `medium` / `high`), `pass_rule` (at most 500); 1 to 60 items; evidence kinds must be in `evidence_rules.allowed_sources` |
| `evidence_rules` | editable | `allowed_sources`, `must_cite` (locked `true`), `max_age_days` (1 to 3,650) |
| `tools[]` | editable inside the group allow-list | `tool_id`, `scope`, `mode` (`read` / `propose`) **by reference only**; an inline tool definition is refused; at most 12 |
| `instructions` | editable | text, at most 5,000 tokens (estimate: UTF-8 bytes / 4), linted |
| `harness` | see below | every field checked against `caps.py` |
| `output_schema` | locked | `{type: assessment_report_v1}` |
| `guardians[]` | mandatory part locked | must contain `pii_mask_v2`, `tool_scope_guard`, `citation_required`; extra guardian ids allowed |
| `eval_pack` | editable | pack id |
| `lifecycle` | platform | `state` (`draft` / `tested` / `approved` / `live` / `retired`), `version` (`1.2` or `1.2.3`), `approvals[]` |

The instruction linter refuses control characters and text that tries to override the platform
preamble (for example "ignore all previous instructions").

### Registry files

`config/factory_tools.yaml`: per tool `tool_id`, `label`, `kind` (`read_facts`, `read_regkb`,
`read_pack_results`, `read_system_record`, `search_documents`), `scope` (kinds `system`, `regkb`,
`pack`, `documents`), `data_class`, `allowed_groups`, `modes` (`read`, `propose`). A tool ref
`scope: "regkb:SBV-TT53-2025"` must use a scope kind of the tool.

`config/factory_groups.yaml`: per group `label`, `roles` (roles of `config/users.yaml` that may
author for the group) and `dimensions` (the dimensions the group owns; each dimension has one
owner). Both loaders (`supervisor.factory.registry`) use strict keys: an unknown or missing key
is an error that names the file and the field.

## Harness

Every agent definition has a `harness` block with six components. Each has a platform default (the
locked part), a bounded editable part and a gate test (WP-F3). Nothing in the harness can call a
tool outside the registry, write outside the run, or act on a bank system. Omit a component to
get its default.

### system_prompt

| | |
|---|---|
| Default (locked) | the platform preamble `platform_v1`: role, output schema, evidence rule, refusal rules, masking rule; always first |
| Editable | the top-level `instructions`, appended after the preamble |
| Cap | 5,000 tokens; linter; `harness.system_prompt.preamble` must be `platform_v1` |

### context

| Field | Default | Editable | Cap |
|---|---|---|---|
| `sources` | `facts_v1`, `pack_results`, `system_record`, `regkb_rows`, `document_sections` (this order) | which sources and their order | only these five, no repeat, at least one; `document` evidence needs `document_sections` |
| `budget_tokens` | 12,000 | yes | 1,000 to 24,000 per call |
| `max_document_chars` | 8,000 | yes | 0 to 20,000 |
| `progressive` | `true` (names first, bodies on demand) | no | locked `true` |

### memory

| Field | Default | Editable | Cap |
|---|---|---|---|
| `run` | `scratchpad` (one run, deleted after) | no | locked |
| `system_memory` | `false` | on or off | when on: `retention_days` and `fields` are required; when off they must be absent |
| `retention_days` | none | with `system_memory: true` | 1 to 365 |
| `fields` | none | `prior_verdicts`, `open_questions`, `waivers` | no repeat |
| `cross_run` | `off` | no | must be `off` in 12B |

No personal data is ever stored; a stored row passes the masker.

### hitl (human in the loop and permissions)

| Field | Default | Editable | Cap |
|---|---|---|---|
| tool modes | `read` only | `permissions[]`: `tool_id` and `mode` (`read` / `propose`) | `act` does not exist; a tool must be in `tools`; a permission cannot widen a `read` tool to `propose` |
| `approval_points[]` | none | `kind: checklist` (a checklist id) or `kind: verdict` (`pass`, `fail`, `not_applicable`, `question`) | at most 20 |
| verdict `fail` on a `high` item; final report | needs a person | no | locked in the runtime |

### verification

| Field | Default | Editable | Cap |
|---|---|---|---|
| `verifier` | `rules` | `rules` or `rules+judge` | the judge re-reads the rationale; it advises |
| locked validators | `evidence_exists`, `quote_matches`, `pass_rule_follows` (always run, before any judge) | no | |
| `validators[]` | none | `evidence_kind_allowed`, `evidence_age`, `rationale_length`, `no_personal_data` | platform list only |

### loop

| Field | Default | Editable | Cap |
|---|---|---|---|
| `mode` | `single_pass` (gather, one structured call per checklist group, verify) | `single_pass` or `loop` | |
| `max_iterations` | 1 | with `mode: loop` | 1 to 8; must be 1 for `single_pass` |
| `stop_when` | `[all_answered]` | `all_answered`, `evaluator_done` | `evaluator_done` needs `mode: loop` |
| `loop_evaluator` | `rules` (coverage, evidence present) | `rules` or `judge` (advisory) | only `rules` for `single_pass` |
| `min_score` | none | required with `judge` | integer 0 to 100; refused with `rules` |
| `budget_tokens` | 60,000 | yes | 1,000 to 200,000 per run |

### Cross-field checks

* every `harness.hitl.permissions[].tool_id` is in `tools`;
* every `approval_points` checklist ref exists;
* the registry check (`python -m supervisor.factory validate`) tests tool ids, modes, scope kinds,
  group access and dimension ownership.

### Choices the platform made (change in `caps.py` on purpose)

The plan fixed `instructions` (5,000 tokens), `retention_days` (365), `max_iterations` (8) and the
modes. The values for the context budget (24,000), the loop budget (200,000), `max_document_chars`
(20,000), the integer score scale (0 to 100) and the three mandatory guardian ids were chosen in
WP-F1 and need the hub to confirm.
