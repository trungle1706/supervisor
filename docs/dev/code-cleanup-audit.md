## 0. Method, and what the tools got wrong

| Tool or check | Result | Caveat found (so the next worker does not repeat the mistake) |
|---|---|---|
| `pylint --enable=duplicate-code --min-similarity-lines=8` | 76 clone blocks | Mostly short blocks. The big ones are the controls / risk / tasks / transparency / alerts CLI and harness clones (D10). |
| Own AST scan: functions with an identical body in 2+ files (4+ lines) | 46 groups | This found the best duplicates (D1, D4, D5, D8, D10, D12). pylint missed them. |

The `mtime_ns` argument of an `lru_cache` function is an intentional cache key (false). After filtering, 24 symbols have zero references anywhere (X3). |
| Own import graph (AST, relative imports resolved) | about 45 modules have no importer in `src/` | Most are `python -m` harnesses or load by `importlib` (K7). A plain grep for the module path gives false "dead" for any module that is imported in a multi-line `from x import (a, b)`. Use the AST graph. |

| Store call scan (AST: `query/get/append/...` inside `for` or a comprehension) | 164 call sites, 56 are `.query(` | Many loops run over a constant set (3 actions, 2 kinds). Section 3.4 lists only loops whose count grows with data. |

Scale: 700 Python files, 205,985 lines in `src/supervisor`; `console/` alone is 35,322 lines; 637 test files, 127,881 lines.

Store facts used in section 3.4 (`adapters/sql/store.py`):
* `read_scope()` (flag `STORE_READ_CACHE`, store lines 112-124) reads a whole **state** table once, then answers later `query`/`get` calls from memory. It does **nothing** for **append-only** tables (26 tables: `verdict`, `agent_event`, `chain_entry`, `chain_payload`, `case_event`, `case_link`, `eval_result`, `risk_evidence`, `control_status`, `task_event`, ...). For those, only an identical repeated query is memoised (line 256).
* `query_by(table, key_col, keys, per_key_limit=...)` (store line 195) is the batch call. It has **one** production caller (`console/readmodels.py::_Prefetch`, line 447). Everything in section 3.4 that is marked "append-only" is a real N+1 even with `STORE_READ_CACHE=1`.
* `STORE_READ_CACHE` is `"0"` in the repo `app.yaml` (line 165-166) and absent from the v0.11.0 filled `app.yaml`. Its own comment says a large Databricks deploy should set it to `"1"`.
